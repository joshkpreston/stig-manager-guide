User Workflow Step-by-step: from login to POA&M generation

The Big Picture

Login → Collection → Assets → STIGs → Reviews → Reports │ Submit / Accept │ Findings → POA&M

Step 1: Authenticate

When you first open STIG Manager, you're redirected to your org's OIDC login page (Keycloak, Okta, etc.). Authentication method depends on your deployment — could be username/password, CAC, OAuth, or magic link.

After login, you're redirected back to STIG Manager with a JWT token that controls your access.

Step 2: Navigate the Interface

The UI has two main areas:

AreaPurpose
Navigation Tree (left panel) Lists your Collections, STIG Library, Interface options, and Admin functions (if applicable). Use this to move between collections.
Content Panel (right area) Shows dashboards, workspaces, and reports. Tabbed interface — you can have multiple open. Use this to work within a collection.

Step 3: Create a Collection

Click +Create Collection in the Nav Tree. Provide a name and description. You're automatically made the Owner.

Tip: Collections don't have to mirror RMF packages. Large packages should be broken into smaller, more manageable collections where users can have higher access and more autonomy.

Step 4: Create Assets

Two ways to add assets:

Manual

From the Collection Configuration tab, click "Create Asset..." — the only required field is Name (must be unique in the collection). You can attach STIGs right away.

Bulk Import

Click "Import CKL or XCCDF..." to create assets and reviews in bulk from existing checklist files. STIG Manager parses the files, creates assets, assigns STIGs, and imports all the review data.

Step 5: Attach STIGs to Assets

Double-click an Asset in Collection Management, then click "Assign STIG" in the popup. You can also go the other way: double-click a STIG and click "Assign Assets."

STIGs must have been imported into the system by an Admin first (see Admin Guide).

Step 6: Grant Users Access

Click "New Grant" in the Grants panel. Pick a user and assign a role:

RoleCan Do
OwnerEverything. Accept/reject reviews. Delete collection.
ManageAdd/remove assets, STIGs, labels, grants (except Owner grants).
FullRead/write all reviews. No management.
RestrictedOnly what the ACL explicitly allows.

For Restricted users, click the target icon to set up their Access Control List — which specific assets, STIGs, or labels they can see.

Step 7: Evaluate STIGs

This is where the actual security work happens. Two workspaces:

Asset Review Workspace

Use when: Evaluating one asset against one STIG, rule by rule.

Open it: From the Collection Dashboard, pick an Asset, then double-click a STIG.

Four panels:

  • STIG Checklist (left) — list of all rules, their status, severity. Click a rule to load it.
  • Rule Content (center) — the rule title, manual check instructions, fix text, CCIs.
  • Review Resources (top right) — reviews of this same rule on other assets (drag & drop to copy), review history, feedback from owners.
  • Review Panel (bottom right) — where you record your evaluation: Result, Detail, Comment.

Collection Review Workspace

Use when: Evaluating the same STIG rule across ALL assets at once.

Open it: From the Collection Dashboard STIGs tab, double-click a STIG.

How it works:

  • Select a Rule in the checklist panel (top left)
  • See all assets and their review status (top right)
  • Double-click Result/Detail/Comment columns to edit inline
  • Results auto-save
  • Bulk Submit/Accept/Reject with toolbar buttons (Shift+click to select multiple)

Review Results & Statuses

ResultMeaning
Not a FindingThe system complies with this rule
OpenThe system does NOT comply — this is a finding
Not ApplicableThis rule doesn't apply to this system
Not ReviewedHaven't evaluated yet
StatusMeaning

Step 8: Reports

Collection Dashboard

Click a Collection in the Nav Tree to see its dashboard:

  • Progress Chart — proportion assessed vs. total, broken down by status
  • CORA Score — risk rating based on open/unassessed findings (see below)
  • Inventory — asset count, unique STIGs, total checklists
  • Findings — open findings by CAT I/II/III severity
  • Review Ages — oldest and newest review dates

CORA Scoring

Cyber Operational Readiness Assessment

Formula: (p1·w1 + p2·w2 + p3·w3) / (w1 + w2 + w3)

Where p = % open+unassessed rules per category, and weights are: CAT I = 10, CAT II = 4, CAT III = 1

RatingThreshold
Very High≥ 20%
High≥ 10% and < 20%
Moderate> 0% and < 10%
LowCAT I = 0; CAT II & III each < 5% unweighted
Very Low0% total

Findings Report

Click "Details" on the Findings box in the dashboard. Shows every Open review, aggregated by Rule, Group, or CCI. From here:

  • Export as CSV
  • Generate a POA&M-style spreadsheet
  • Drill into individual findings to see contributing assets

Note: The POA&M export is a reference/starting point, not a replacement for your official eMASS POA&M.

Metrics Export

Export dashboard data in multiple groupings (Collection, Asset, STIG, Label, Ungrouped) and styles (Summary or Detail) as CSV or JSON. Useful for feeding into Grafana, PowerBI, or custom dashboards.
