Admin Guide Application management: STIG imports, users, jobs, and monitoring

Admin vs. Owner

Admin (Application Manager) = app-wide privileges set in your OIDC provider. Can import STIGs, manage all collections, manage users.

Owner = per-collection role set within STIG Manager. Can manage assets, grants, accept/reject reviews in their collection.

These are independent. An Admin doesn't automatically have access to collection data — they still need a Grant.

Admin Responsibility #1: Import STIGs

This is the most important admin task. STIG Manager cannot function without imported reference STIGs. No STIGs = no assignments, no evaluations, no metrics.

How to Import

  1. Download STIGs from DISA (quarterly compilations or individual STIGs)
  2. In STIG Manager: Application Management → STIG Benchmarks → "Import STIGs"
  3. Upload the .zip files directly (you can upload entire quarterly compilation archives)
  4. Wait for processing (may take several minutes for full compilations)

Important Notes

  • Do this quarterly when DISA releases new compilations
  • By default, existing revisions are not overwritten — check "Replace existing Revisions" if needed
  • When a new revision is imported, it becomes the default for all assets automatically
  • Most reviews carry forward because STIG Manager matches by check content hash
  • Consider deleting old revisions (>1 revision back) to keep the database lean

Admin Responsibility #2: Manage Users

Key Distinction

Creating users and assigning privileges (admin, create_collection) happens in your OIDC provider (Keycloak, Okta, etc.). STIG Manager cannot do this.

Managing collection grants and group membership happens in STIG Manager.

User Lifecycle

ActionWhereWhat Happens
Create user OIDC Provider User can now authenticate
First login Automatic STIG Manager creates a user record from the JWT claims
Pre-register STIG Manager Create a user record before first login (username must match exactly). Lets you assign grants in advance.
Grant access STIG Manager Assign the user a role in specific collections
Set Unavailable STIG Manager Removes all grants and group memberships. User can't see any data. Record kept for audit.
Unregister STIG Manager Removes all grants. User record retained for attribution. Does NOT prevent login — must also disable in OIDC provider.

User Groups

Only Admins can create groups and manage membership. Once a group exists, any Collection Owner/Manager can grant it access to their collection.

Useful for: "All Windows admins get Full access to the Windows Servers collection."

Admin Responsibility #3: Service Jobs

Enable These!

Service Jobs are disabled by default. Enable them to keep your database healthy.

JobWhat It DoesRecommended Schedule
Cleanup Database Removes records from deleted Collections and Assets Weekly
Delete Unmapped Reviews Removes reviews that don't match any STIG Rule in the system (from deleted old STIGs) Monthly
Delete Unmapped Asset Reviews Removes reviews for STIGs no longer assigned to assets Every 90 days

Job Tasks Available

  • WipeDeletedObjects — removes soft-deleted records
  • DeleteUnmappedReviews — cleans orphaned reviews
  • DeleteUnmappedAssetReviews — cleans asset-specific orphaned reviews
  • AnalyzeReviewTables — runs MySQL ANALYZE TABLE for query optimization

Schedule during off-peak hours. Run any job immediately with "Run now..." button. Always have backups before enabling for the first time.

Admin Responsibility #4: Monitor the App

Application Info Panel

Application Management → Application Info. Tabs include:

  • Requests — API endpoint stats: counts, durations, errors, users/clients
  • Collections — size, grants, labels, STIG assignments, settings per collection
  • Users — privileges, grants, last activity (30/90 day summaries)
  • Groups — user counts, grants, creation dates
  • MySQL — database config, status, managed data stats
  • NodeJs — version, uptime, memory usage

Reports can be saved as JSON and shared with the STIG Manager team for troubleshooting (with option to anonymize names).

Log Stream

Application Management → Log Stream. Real-time WebSocket streaming of backend logs directly in the browser. Features:

  • Filter by log level and component
  • Record to file (not available in Firefox)
  • JSON tree view of individual log entries
  • API transactions grid with correlated log entries

Requires WebSocket support in your reverse proxy. Enabled by default; disable with STIGMAN_EXPERIMENTAL_LOGSTREAM=false.

App Data Export/Import (Experimental)

Streams the entire database as JSONL. Can be imported into another instance. ALL data in the destination is replaced.

Enable with STIGMAN_EXPERIMENTAL_APPDATA=true. Breaking changes may happen. Rely on database backups.

Automated Evaluation Imports

STIGMan Watcher

A CLI utility that monitors filesystem directories for .ckl/XCCDF files and auto-imports them into a Collection. Perfect for integrating with scanning tools like Evaluate-STIG and SCC.

Setup:

  1. Install from npm: npm install -g stigman-watcher
  2. Configure with your STIG Manager URL and target Collection
  3. Point it at the directory where your scanning tools dump results
  4. Grant the Watcher's service account permissions on the Collection

See the Ecosystem page for more details.
