Entity Relationships ER Diagram

The two independent domains: the system-wide STIG Library (managed by admins) and per-Collection assessment data (managed by users). Reviews connect the two via a content-based key, not a direct foreign key to a STIG revision.

erDiagram

    STIG ||--|{ REVISION : "has versions"
    REVISION ||--|{ RULE : contains
    RULE ||--|| CHECK_CONTENT : "has unique"

    COLLECTION ||--|{ ASSET : contains
    COLLECTION ||--|{ GRANT : "access via"
    COLLECTION ||--|{ LABEL : "organizes with"
    COLLECTION ||--|{ REVIEW : stores

    ASSET ||--|{ STIG_ASSIGNMENT : "assigned"

Key Insight: Review Keying

Reviews are not children of a STIG Assignment. They're keyed by Rule Version + SHA-256(Check Content). This is what makes STIG revision updates seamless — if the check content hasn't changed, the existing review automatically appears under the new revision.

Authentication Flow Sequence Diagram

sequenceDiagram
    actor User
    participant Browser as Web Client
    participant OIDC as OIDC Provider
(Keycloak)
    participant API as STIG Manager API
    participant DB as MySQL

    User->>Browser: Open STIG Manager
    Browser->>OIDC: Redirect (Auth Code + PKCE)
    User->>OIDC: Authenticate (password / CAC / OAuth)
    OIDC->>Browser: Authorization Code
    Browser->>OIDC: Exchange code for tokens
    OIDC->>Browser: Access Token (JWT) + Refresh Token

    Note over Browser,API: All subsequent requests include JWT

    Browser->>API: GET /collections (+ JWT)
    API->>OIDC: Fetch JWKS (cached)
    API->>API: Validate JWT signature & claims
    API->>API: Extract username, privileges, scopes
    API->>DB: Query collections for user
    DB->>API: Collection data
    API->>Browser: JSON response

    Note over Browser,OIDC: When token expires...

    Browser->>OIDC: Refresh token (silent)
    OIDC->>Browser: New Access Token

Review Lifecycle State Diagram

stateDiagram-v2
    [*] --> Unreviewed: Asset + STIG assigned

    Unreviewed --> Saved: Evaluator records result
    Saved --> Saved: Evaluator modifies
    Saved --> Submitted: Evaluator submits
(meets collection requirements)
    Submitted --> Accepted: Owner accepts
    Submitted --> Rejected: Owner rejects
(with feedback)
    Rejected --> Saved: Evaluator revises
    Saved --> Submitted: Re-submit

    Accepted --> [*]: Assessment complete

    note right of Unreviewed
        No result recorded yet.
        Counts as "unassessed"
        in CORA scoring.
    end note

    note right of Saved
        Result recorded but not
        submitted for validation.
        Valid results: Open,
        Not a Finding, Not Applicable
    end note

    note left of Rejected
        Owner provides feedback.
        Shows in evaluator's
        "Rejected Reviews" report.
    end note
