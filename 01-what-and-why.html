What Is STIG Manager & Why Does It Exist? Understanding the problem before the solution

The Problem

In the DoD (Department of Defense), every information system must be assessed against STIGs — Security Technical Implementation Guides published by DISA (Defense Information Systems Agency). These are security checklists. Each STIG contains hundreds of individual rules like:

  • "Ensure password minimum length is 15 characters"
  • "The system must use TLS 1.2 or higher"
  • "Unused accounts must be disabled after 35 days"

There are STIGs for everything: Windows, Linux, databases, network devices, web servers, applications, and more. A typical system might have 5-20 STIGs assigned to it, each with 100-300+ rules.

Without STIG Manager

Teams track compliance with:

  • .ckl files — XML checklists from STIG Viewer, one per asset per STIG
  • Spreadsheets — manual tracking of who checked what
  • Shared drives — folders full of files with names like Server01_Win10_STIG_v2r3_FINAL_FINAL2.ckl

The Pain Points

  • No single source of truth — everyone has different versions of files
  • No real-time visibility into assessment progress
  • When DISA releases new STIGs quarterly, starting over from scratch
  • No way to review the same rule across multiple assets at once
  • Generating POA&Ms is manual and error-prone
  • No audit trail of who changed what

The Solution

STIG Manager puts all assessment data in one place with one view that everyone shares.

What You Get

  • Single source of truth — all reviews in one database, role-based access
  • Real-time dashboards — see completion rates, findings by severity, risk scores
  • Smart STIG updates — when DISA releases new versions, only rules with changed check content need re-evaluation
  • Bulk operations — review the same rule across all assets at once
  • Import/export — bring in .ckl, .cklb, XCCDF files; export them back out
  • Automation via API — REST API for integrating with scanning tools
  • POA&M generation — export findings as POA&M-style spreadsheets

Who It's For

RoleHow They Use STIG Manager
System Admins Record compliance status in real-time as they harden systems
Security Analysts / Evaluators Perform STIG assessments, import scan results, document findings
ISSOs / Security Managers Track assessment progress, accept/reject reviews, generate reports
RMF Teams Manage the overall assessment lifecycle, generate POA&Ms for eMASS

Where It Fits in the RMF Process

STIG Manager primarily supports:

  • RMF Step 3 — Implement Security Controls
  • RMF Step 4 — Assess Security Controls
  • RMF Step 6 — Monitor Security Controls (tracking review ages, re-evaluation when STIGs update)

It does not replace eMASS, SCAP scanners, or other tools. It's the assessment tracking layer that connects them.

Core Concepts (Vocabulary)

TermWhat It Means
Collection The primary organizational unit. Groups assets together. Can mirror an RMF package or any other grouping.
Asset A host, server, device, or system being assessed.
STIG A DISA security checklist assigned to an asset (e.g., Windows 10 STIG, Apache STIG).
Rule A single check within a STIG (e.g., "Password must be 15+ characters").
Review Your evaluation of a rule on an asset: Open (finding), Not a Finding, or Not Applicable.
Grant A user's role/permission within a specific collection (Owner, Manage, Full, or Restricted).
Label A tag you can apply to assets for filtering and grouping.
